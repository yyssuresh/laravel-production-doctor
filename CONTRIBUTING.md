# Contributing

Thanks for considering a contribution.

1. Open an issue to discuss substantial changes before starting work.
2. Keep checks read-only by default and avoid booting the target Laravel application.
3. Never print or commit `.env` contents, application keys, passwords, tokens, or production host details.
4. Add tests for new checks and edge cases.
5. Run `composer test` and `composer check` before opening a pull request.
6. Explain platform-specific assumptions and document false positives.

By submitting a contribution, you agree that it may be distributed under this project's MIT licence.
